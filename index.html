THE PROJECT

From leading software development to building a game myself.

After years working in software product ownership, technical project management and cross-team coordination, I wanted to experience game development from the developer's perspective.

Redneck Rumble is my independent learning project, connecting asset production, character animation, combat systems and iteration into a playable prototype. This portfolio documents both the work and the production lessons behind it.

Hannu Kukka · Technical product leadership & hands-on game development

AI tools & asset attribution

All 3D assets presented as my own work were created by me. AI tools have supported concept exploration, texturing, debugging and learning.

Some environment assets are third-party resources (CC0 or FAB marketplace), and certain temporary 2D UI assets are AI-generated.

Character animations include assets sourced from Mixamo and Epic Games' Lyra Starter Game and Game Animation Sample projects. I have handled character rigging, animation retargeting, blending, locomotion systems and gameplay integration myself.

All showcased Blueprint gameplay systems have been implemented and integrated by me, with help from AI tools in debugging and optimization.

03 / TECHNICAL CHALLENGES

Debug. Iterate. Integrate.

Getting character systems to cooperate across unarmed, pistol and rifle states while preserving aiming, reloading, hit reactions and foot placement.

Animation system integration

My approach is iterative: isolate a problem, inspect the relevant skeleton or Blueprint state, test one change and validate in gameplay.

For example, one character-positioning bug came from an unexpected transform override in the character Blueprint, not from the mesh itself. Tracing the dependency prevented an unnecessary asset rework.

05 / PRODUCTION PERSPECTIVE

What building it taught me.

01

Technical dependencies

Changes to rigs, animations and weapon systems ripple across the gameplay stack. Early integration and clear interfaces reduce surprises.

02

Iterative delivery

A small playable feature delivers more useful feedback than a collection of disconnected, unfinished assets.

03

Creative trade-offs

Visual ambition must be balanced against maintainability, performance and implementation effort.

04

Developer empathy

Removing friction, documenting decisions and protecting focus time matter to the people building the product.
